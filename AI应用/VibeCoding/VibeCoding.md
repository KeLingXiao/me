# VibeCoding(氛围编程/感觉编程)

不管是 MCP, Skill, Rules, AGENTS.md/CLAUDE.md 这些都是为了更好的让 LLM 输出高
质量的回答, 它们最终都会作为 一次对话的 Prompt 发送给 LLM, 这里就涉及到多个技术 RAG, Memory 管理 的技术

## 指令 质量决定输出高低

在我们传统开发中 一个项目通常需要有 产品需求, 需求评审, 架构设计, 测试, 运维部署 等等. 但是 AI 时代 一人即团队, 你就是该项目的负责人, 需要将从 程序员 到 产品负责人 角色上的转变 这一步是让你用好 工具的前提. 不能一上来就去想如何做 前面的步骤比如何做更加重要

**Agent 可以是 架构师, 产品经理, 测试运维专家 它的角色由你负责, 所以你可以理解 它的下限是非常高的, 它的上限取决于你的上线**

别人通过 VibeCoding 可以做出一个 企业级可交付的 应用 而你 做出来的是玩具, 为什么呢? 这里有几个原因 `Prompt, 产品边界, 约束(架构约束), 技术规范, 记忆管理` 这些原因使得你和其他人 VibeCoding 出来的质量差距的主要因素, 你可以理解 ==输入质量 和 输出质量 线性关系 而是 指数关系== AI需要 **猜架构, 猜标准, 猜质量, 猜方案 只要其中一步错误** 那么后续. 也就是说 我们的 Prompt 给的越清晰 那么 输出的质量就越高 越可以达成我们的目标

这里我们就可以总结一句话: ==你的 指令越清晰 AI 可以给出的越准确, 如果指令不清晰 那么 AI 给出的 会偏离你的预期 所以 AI输出质量高低 更多在于你 如何 **提出问题**==

当前还有非常火热的 **许愿式编程**

## 精力分配

在当前时代模型越强我们越需要注重架构的培养, 什么是架构师呢? 架构师能做什么呢?

- 架构师主要在做的就是 定义产品边界, 要做什么方向 不错什么方向, 什么该做什么不该做, 要做到什么程度, 要做到什么标准
- 架构师不写具体业务代码, 而是需要实现 系统规范标准(代码如何写, 错误如何处理, 接口如何定, 方案如何涉及)
- 当出现 A 和 B 技术 应该如何做取舍
- 验收标准 团队交付的东西是否是他想要的东西

你可以理解 当前的 Coding Agent 都是我们的工厂团队 而我们需要做的就是将 角色的转变 与 架构的设计 方向之间的转变

这里我们来举一些例子 来学习如何进行提问!
对于非优质的 Prompt 我们需要花费更多的 Token 让其进行思考输出, 而 优质的 Prompt 就会减少 思考时间 与 Token 消耗, 因为对于非优质的 Prompt 模型需要考虑的问题会更多 所以花费的 Token 数量会较多

这里我有提供 [DESIGN.md](./prompt/1.design.md) 供你查看, 重点还是需要看结构 和 设计方案

```
非优质 Prompt example
请你使用 NestJS 来实现一个 Chat 服务

优质 Prompt example
请你按照我在 DESIGN.md 中的设计方案进行实现(其中包含 接口规范, 使用技术, 错误码定义, 连通性测试)
```

你可以发现两种 Prompt 但是输出的质量是完全不同的, 那么不懂技术的同志就问来了 我不懂技术可以做到这样吗?
我的回答是当然的, 你还是需要了解一些语言基本概念 以及 架构设计方面的知识, 在这就是 **提问的智慧** 这一门课程

从最找GPT出现我们从 日常文案处理 到 现在 转变为 工程团队 帮我们写代码并交付 我们的关注点也从 代码量 到 精细度 的角度之间转换
现在我们写代码 应该要从 写代码, 找BUG, 测试用例, 文档 的精力 转换到 设计 架构, 边界, 标准, 取舍 这些关注点上, 这个改变是可复利的, 就像我们计算机必须先学习的 语言 -> 数据结构 -> 操作系统/网络 这一步 它是可以为我们未来带来更大的收益

### 你需要做什么? AI 需要做什么?

这里我总结全链路下来可能遇到的问题 这几个方法 你可以拿来即用

1. 你需要做的:

- 产品边界
- 架构决策
- 技术取舍
- 一致性
- 举例子: 你要做系统 你要做 单体架构还是微服务架构, 两个技术一致(需要解决的问题 相似)你要考虑哪些问题 与 场景. 你可以让 CodingAgent 给你方案 但是你需要自己审核修改

2. AI 需要做的: AI写的任何一行代码你都需要知道作用

- 开发验收(AI做 你需要验收)
  - 接口开发/业务代码(前后端)
  - 测试用例
  - 文档撰写
- Coding 标准化(AI 全权处理)
  - 模块化规范, 团队的 语法规范
  - 格式化
  - 启动脚本
